# 智优 Pre-Legal Self-Check v2（送审前自审核规则）

## 定位
在内容送 Legal/PR/Tax 人工审核之前，智优系统先按照以下规则自动扫描，标记潜在风险点。
- **通过 = 可直接发布**（无需 Legal 审核的类目）或**可送审**（需 Legal 审核的类目）
- **警告 = 需人工确认后再送审**
- **阻断 = 必须修改后才能送审**

数据来源：
- Content Review SOP (Dec 2025)
- Legal Questionnaire for Content Review (Sep 2025)
- Playbook 日常内容审核指南 (Nov 2020, bilingual)
- Privacy Compliance Legal Requirements in RoA (Dec 2025)

## ⚠️ 预审执行原则（v2 核心改进）

### 原则 1：语境优先，regex 辅助
- 所有规则的触发条件 = **regex 命中 + 语境确认**
- regex 只是"候选标记"，最终判定必须结合上下文
- 如果 regex 命中但语境合理（如引用官方费率、否定句式、口语化比喻），标记为 `CONTEXT_OK` 而非告警

### 原则 2：分级严格度
| 内容类别 | 预审严格度 | 说明 |
|---------|----------|------|
| Critical=5（注册/费用/税务/合规） | 🔴 严格 | 所有规则全量检查 |
| Critical=4（站点/选品/运营） | 🟡 标准 | 跳过口语化表述检查（A4 平台/市场词） |
| Critical=3（入门/科普/广告） | 🟢 宽松 | 仅检查 BLOCKED 级别规则 |

### 原则 3：白名单豁免机制
以下场景自动豁免，不触发告警：
1. **官方费率引用** — 引用 Seller Central 公开费率（如"39.99美元/月"、"8%-15%佣金"）+ 标注来源链接 → 豁免 L2/A5
2. **否定/对比句式** — "亚马逊不是XXX的平台" → 豁免 A4_platform
3. **已有 disclaimer** — 段落末尾/脚注含"仅供参考"/"以实际为准"/"数据来源" → 豁免 L2/A5/E2
4. **第三方工具泛称** — 使用"第三方XX工具"而非具体品牌名 → 豁免 A6
5. **限定性表述** — "之一"/"可能是"/"相对较"/"通常" 已附带 → 豁免 A4_absolute
6. **引用卖家平台内产品名** — "FBA"/"Sponsored Products"/"Brand Registry" → 豁免 A4_platform

### 原则 4：合并去重
- 同一篇文章中，同类问题只报一次（取最严重的实例）
- 如果 Step 3.6 已修正某问题，Step 3.7 不再重复报告
- 输出报告按 P0/P1/P2 优先级排序，最多报 5 条 actionable findings

## 第一层：是否需要 Legal 审核（SOP 判定）

根据 Content Review SOP，系统先判定内容是否需要送 Legal 审核：

| 审核类型 | 需要审核的情况 | 不需要审核的情况 |
|---------|--------------|----------------|
| **Legal** | ① VP/Director 发言的大型活动材料 ② 全新 seller-facing Amazon 服务/项目发布公告 ③ 法规描述(GDPR/VAT/Payment等) | Press releases, 官网更新, 促销, 社交媒体, 卖家大学, 案例故事, 邮件, 卖家问卷 |
| **PR** | 所有 public-facing 内容（微信、微博、头条、抖音等） | Seller-facing 内容（1:1/1:many 卖家沟通、邮件、QQ/微信群、直播、卖家大学、卖家调研） |
| **Tax** | 所有新建内容 | — |

### 自审规则
```
IF content_category IN ["VP/Director活动演讲", "全新服务/项目发布", "法规描述"]:
    legal_review_required = TRUE
    IF content_category IN ["全新服务/项目发布", "法规描述"]:
        mp_signoff_required = TRUE  # 需先获取 Marketplace 审批
ELSE:
    legal_review_required = FALSE

IF channel IN ["微信", "微博", "头条", "抖音", "公众号", "小红书", "公开网页"]:
    pr_review_required = TRUE
ELSE:
    pr_review_required = FALSE

tax_review_required = TRUE  # 所有新内容都需要
```

## 第二层：Legal Questionnaire 自动扫描（8项检查）

对每篇内容自动扫描以下 8 个维度，标记 PASS / WARNING / BLOCKED：

### Check 1: Amazon Logo/品牌使用
- **扫描**: 内容是否提及使用 Amazon logo 或品牌元素
- **规则**: 如使用，必须符合 Amazon Logo 使用规范
- **自审**: 检测是否有第三方 logo 与 Amazon logo 平行出现 → WARNING
- **Playbook 规则**: 不与第三方 logo 在宣传材料中平行使用

### Check 2: 外部数据引用
- **扫描**: 是否引用了外部/第三方数据
- **规则**: 
  - 外部数据需来自权威机构、标明完整出处
  - 需加 disclaimer: "本文内容基于第三方数据，仅供参考，不代表亚马逊的建议"
- **自审**: 检测数据引用但无出处标注 → BLOCKED
- **检测模式**: `\d+%|数据显示|据.*统计|研究表明|报告指出`

### Check 3: 内部 Amazon 数据
- **扫描**: 是否包含内部数据（排名、GMS、增长率等）
- **规则**: 
  - Seller-specific data 绝不能对外披露
  - Aggregated data 需经 Legal/PR/Business 审批
  - 使用官方已公开数据需确保是最新版本
- **自审**: 检测到具体数字+Amazon业务指标 → WARNING
- **检测模式**: `MAU|GMS|GMV|活跃用户|卖家数量|增长率\d|排名`

### Check 4: 第三方知识产权
- **扫描**: 是否使用第三方商标、logo、图片等
- **规则**: 需签署授权及承诺函
- **自审**: 检测到非 Amazon 品牌名出现在推荐/背书语境 → WARNING
- **Playbook 规则**: 不使用网络下载的著作权不明图片

### Check 5: 个人信息收集/存储
- **扫描**: 内容是否涉及收集或存储个人数据
- **规则**: 
  - 需事先获得数据主体同意
  - 存储只能用经 InfoSec 审批的工具（Qualtrics/RSVP）
  - RoA 地区需遵守当地隐私法（VN/KR/TW）
- **自审**: 检测到个人信息收集相关表述 → WARNING
- **检测模式**: `收集.*信息|填写.*表|联系方式|手机号|邮箱|consent|同意`

### Check 6: 地图使用
- **扫描**: 内容是否包含地图或地图元素
- **规则**: 
  - 只能使用中国测绘主管部门提供的具审图号的公益性地图
  - 不做任何改动
  - 建议用国旗替代地图指代国家
- **自审**: 检测到"地图"相关内容 → WARNING
- **检测模式**: `地图|国境|边境|领土|版图`

### Check 7: 已审批内容复用
- **扫描**: 是否基于此前已审批的内容
- **规则**: 对已审批内容的整合/汇总不需要新的审核（除非原审批附带特殊条件）
- **自审**: 如标记为复用已审批内容 → 可跳过 Legal 审核

### Check 8: 其他法律风险
- **自审**: 综合检测以下风险信号 → 任何一项触发 WARNING

## 第三层：Playbook 合规规则（General + Legal + PR + Tax）

### A. General Guidelines 检查项

#### A1: Copyright 脚注
- **规则**: 每页页脚必须有 `Copyright © 20XX Amazon. All rights Reserved.`
- **自审**: 检测内容是否包含 copyright 声明 → 如缺失 WARNING

#### A2: 内部信息泄露
- **禁止**: 具体办公地址、团队组织架构图、管理结构、汇报线
- **检测模式**: `汇报|org chart|组织架构|办公室地址|部门结构`
- **触发**: BLOCKED

#### A3: 产品/项目如实描述
- **禁止**: 夸大/不实描述产品功能或效果
- **禁止**: 透露未正式推出的产品/服务/站点
- **规则**: 产品名称使用官方正式名称（中英文一起）
- **检测保证性陈述**: `一定能|必定|保证.*增长|确保.*销量|100%`
- **触发**: BLOCKED

#### A4: 禁用词及替代词

| 禁止使用 | 应替换为 |
|---------|---------|
| 市场/细分市场 | 站点/国家/地区/行业 |
| 平台/亚马逊平台 | 网站/站点 (卖家平台除外) |
| 生态/生态系统/生态圈 | 服务/产业服务集群 |
| 最好/最佳/顶级/第一品牌/最佳实践 | 领导者/最好的选择之一/优选/实践分享 |
| 保证性陈述 | 客观性陈述 |
| 合作伙伴 | 第三方服务提供商 |
| 伙伴/合伙关系/联盟 | 建立合作/签署合同 |
| 最终解释权归亚马逊所有 | 亚马逊保留对本项目/活动的解释权 |

#### A5: 数据使用规范
- **外部数据**: 权威机构+最新+完整出处+disclaimer
- **内部数据**: 仅可用已公开数据(股东信/财报)，标注为最新
- **Aggregated data**: 标注保密信息+脚注"亚马逊研究，20XX年"
- **禁止**: 披露 Seller-specific data、未经审批的 aggregated data
- **检测**: 出现具体业务数字无出处标注 → BLOCKED

#### A6: 第三方/服务商相关
- **禁止**: 给服务商"官方认可/指定/合作"名号
- **禁止**: 单独推荐某个服务商
- **规则**: 维持"独立方"表述
- **检测模式**: `官方认可|指定服务商|合作伙伴|推荐.*服务商|官方推荐`
- **触发**: BLOCKED

### B. Legal Specific 检查项

#### B1: 第三方 IP 使用
- **规则**: 需授权及承诺函
- **禁止**: 使用网络直接下载的著作权不明图片
- **禁止**: 截取社交媒体未授权的文字/剧照
- **禁止**: 卖家故事中直接出现推荐注册/使用某产品的内容

#### B2: 个人信息收集
- **规则**: 收集前获得同意、分享给第三方前获得同意
- **存储**: 仅限 Qualtrics 和 RSVP
- **禁止**: 问卷星等非审批工具

#### B3: 地图使用
- **规则**: 必须有审图号+不得修改
- **替代方案**: 国旗代替地图

### C. PR Specific 检查项

#### C1: 敏感话题
- **禁止**: 政治/社会敏感/争议议题
- **规则**: 台湾→中国台湾，香港→中国香港，澳门→中国澳门
- **检测**: `台湾(?!.*中国)|(?<!中国)香港|(?<!中国)澳门` → BLOCKED (应加"中国"前缀)
- **禁止**: 种族歧视、LGBT 争议性设计、评论国际关系
- **禁止**: 夸大"中国制造"在国外影响力

#### C2: 竞品对比
- **禁止**: 与友商进行比较
- **规则**: 突出亚马逊自身优势与特点
- **检测**: `对比.*Shopee|vs.*速卖通|比.*eBay.*好|优于.*TikTok`
- **触发**: BLOCKED

#### C3: COVID-19
- **禁止**: 评论全球/中国/其他国家疫情
- **禁止**: "疫情带来巨大商机"类表述
- **检测**: `疫情.*商机|疫情.*机遇|疫情.*刺激`
- **触发**: BLOCKED

#### C4: Prime Day 日期
- **禁止**: 官方发布前在公开渠道提及 PD 日期
- **检测**: `Prime Day.*日期|PD.*时间|Prime Day 20\d{2}年\d{1,2}月`
- **触发**: WARNING (需确认是否已官方发布)

### D. Tax Specific 检查项

#### D1: 业务活动描述（境外实体产品/服务）
- **禁止词**: 招商、销售(sales)、招募(seller recruiting)、筹划、策略、战略、协议定价
- **允许词**: 建议、咨询、支持、卖家专业支持、协助、拓展、卖家宣传
- **检测模式**: `招商|seller recruiting|筹划|策略|战略|协议定价`
- **触发**: BLOCKED

#### D2: 卖家注册/认证表述
- **规则**: 必须清晰表明"通过亚马逊卖家平台注册"，非全球开店官网
- **禁止**: "前往全球开店官网注册"、"扫码注册"(导向 leads form)
- **禁止**: "我们将审核"(应改为"亚马逊将审核")
- **检测**: `全球开店.*注册|扫码.*注册|我们.*审核|我们的.*要求`
- **触发**: BLOCKED

#### D3: 品牌使用（亚马逊全球开店 vs 亚马逊）
- **规则**: 介绍境外站点产品/工具时，服务提供方必须是"亚马逊/亚马逊XX站"，不是"全球开店"
- **禁止**: "全球开店将推出X工具"（应为"亚马逊将推出X工具"）
- **禁止**: 在境外产品品牌前加全球开店 logo
- **检测**: `全球开店.*推出|全球开店.*工具|全球开店.*站.*注册`
- **触发**: WARNING

#### D4: 税务政策引用
- **规则**: 只能直接引用中国税务机关官方政策+标明来源
- **必须附声明**: "本政策来自国家税务总局网站...仅供参考，不代表亚马逊对相关政策的解读..."
- **禁止**: 对税务政策做出解读、使用倾向性语言
- **检测**: `根据.*文件.*可以享受|税务.*建议|税务.*解决方案`
- **触发**: BLOCKED

#### D5: 免费提供商品/服务
- **规则**: 亚马逊中国实体向卖家提供"免费服务/礼物/赠品"需税务部批准
- **检测**: `免费服务|免费礼物|赠品|免费提供`
- **触发**: WARNING (需确认是否已获税务部批准)

## 第四层：RoA 隐私合规检查（VN/KR/TW）

当内容目标市场涉及 VN、KR、TW 时，额外检查：

### Privacy Check 1: 个人数据收集同意
- **规则**: 必须获得数据主体明确事先同意
- **KR 特别规则**: 不同处理类型需分别获得同意（收集使用/第三方提供/跨境传输）
- **TW 特别规则**: 敏感数据需书面同意

### Privacy Check 2: 跨境数据传输
- **KR**: 需单独同意 + 隐私政策披露
- **TW**: 对中国大陆有限制令（通讯业/社工/人力资源）
- **VN**: 需提交 CTIA 评估报告

### Privacy Check 3: 个人信息安全措施
- **通用**: 必须实施适当安全保护措施
- **TW**: 数字经济行业需制定"个人资料档案安全维护计划"

### Privacy Check 4: 数据泄露通知
- **VN**: 侵害数据主体权益时通知主管机关
- **KR**: 发生泄露需通知数据主体+报告监管机构
- **TW**: 72小时内报告数字发展部

## 与现有 run_zhiyou_compliance 的关系

| 维度 | 现有 compliance (Step 3.6) | Pre-Legal Self-Check (新增) |
|------|---------------------------|---------------------------|
| 定位 | 内部敏感词+禁用词扫描 | 模拟 Legal/PR/Tax 审核视角 |
| 规则来源 | content-rules.md 禁用词表 | 4份正式审核文件 |
| 输出 | PASS/FIXED/BLOCKED | PASS/WARNING/BLOCKED + 详细 findings |
| 时机 | 智优流水线内自动执行 | 在送人工审核前的最后检查 |
| 目标 | 消除明显违规 | 减少被 Legal 打回的概率 |

**建议执行顺序**: 智优评分 → 智优重写 → 合规审查(Step 3.6) → **Pre-Legal Self-Check** → 送审/发布
